BUSNEXA ROUTE ENGINE NOTES — MULTI-CORRIDOR UPDATE

WHAT CHANGED
- Main search still geocodes both entered locations in India and uses OpenStreetMap / OSRM road geometry.
- The route engine first requests OSRM alternatives, then tries a limited set of mapped intermediate-town waypoints that fall near the origin-destination corridor.
- It keeps up to three distinct road corridors after checking the returned geometry, distance and endpoints.
- Where a waypoint route is returned, the town is displayed as a route waypoint and the route label identifies the via-town corridor.
- Route variants use staggered demo departure offsets of 20 minutes (0, 20, 40 minutes) while preserving the base sample timetable pattern.
- Each route's OSRM road distance is carried into the service result and fare calculation, so longer road routes receive a higher estimated fare under the prototype fare-per-km rule.
- A single moving bus marker is displayed. The duplicate fixed destination bus marker was removed.
- Stops behind the simulated bus are marked as crossed; upcoming stops remain visually distinct.

IMPORTANT DATA LIMITATIONS
- These are road-route previews, not verified bus operator itineraries. OSRM calculates car-driving roads and cannot confirm that a bus operator uses the same corridor.
- Intermediate town markers generated by the route engine are map waypoints, not verified boarding stops.
- Operator names, service numbers, timetables, coach types, fares, seat inventory and vehicle movement remain DEMO data. The 20-minute offsets are generated sample timings, not published operator departures.
- No complete all-India operator schedule feed or real-time GPS feed is integrated. Use operator GTFS/static timetable feeds and authorised GPS/AVL feeds before describing services as real.
- The public OSRM demo server may return fewer alternatives, rate-limit requests or be temporarily unavailable. The app shows only the routes it successfully retrieves; it must not fabricate missing routes.

VALIDATION
- server/index.js and client/src/data.js pass Node syntax checks.
- App.jsx passes the TypeScript JSX parser check.
- A full Vite production build and live external OSRM/Nominatim requests were not run in this packaging environment.
